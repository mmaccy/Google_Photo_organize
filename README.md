# Google フォト 容量整理ツール

Google フォトで**保存容量を消費している**写真・動画だけを対象に、

1. ローカルにダウンロードして保存
2. 保存の成功を確認できたものだけ Google フォトから削除(ゴミ箱へ移動)

を自動で繰り返すツールです。**Pixel 特典などで容量を消費していないメディアは対象になりません。**

## 仕組み — なぜ「容量を消費しているものだけ」を選べるのか

Google フォト Web 版のストレージ管理ページ
[photos.google.com/quotamanagement/large](https://photos.google.com/quotamanagement/large)
は、**アカウントの保存容量を消費している写真・動画だけ**をサイズの大きい順に表示する公式ページです。
以下のような「容量にカウントされない」メディアはこのページに表示されません。

- Pixel 特典(Pixel 1 の元の画質無制限、Pixel 2〜5 の保存容量の節約画質無制限など)でアップロードしたもの
- 2021 年 6 月 1 日より前に「高画質(保存容量の節約画質)」でアップロードしたもの

このツールはこのページを Playwright(ブラウザ自動操作)で巡回し、1 件ずつ
「ダウンロード → 保存成功を確認 → ゴミ箱へ移動」を繰り返します。
**ダウンロードが確認できなかったものは削除しません。**

### なぜ API ではなくブラウザ自動操作なのか

Google Photos の公式 API では今回の要件を実現できないためです。

- 写真・動画を**削除する API は存在しません**
- 2025 年 3 月末の仕様変更により、Library API では自アプリがアップロードしたもの以外の**ライブラリ全体を一覧できなくなりました**
- 「容量を消費しているかどうか(Pixel 特典対象かどうか)」を判別できる情報も API にはありません

## セットアップ

**ローカル PC(Google アカウントにログインできる環境)で実行してください。**
Python 3.10 以上が必要です。

### Windows (PowerShell)

```powershell
git clone https://github.com/mmaccy/google_photo_organize.git
cd google_photo_organize
python -m pip install -r requirements.txt
python -m playwright install chromium
```

- PowerShell では `&&` が使えないことがあるため(標準の PowerShell 5.1 は非対応)、1 行ずつ実行してください。
- `pip` / `playwright` コマンドが認識されない環境でも動くよう、`python -m` 経由の実行を推奨します。
- `python` が見つからない場合は `py -m pip ...` / `py -m playwright ...` を試してください。

### macOS / Linux

```bash
git clone https://github.com/mmaccy/google_photo_organize.git
cd google_photo_organize
pip install -r requirements.txt
playwright install chromium
```

## 使い方

### 1. ログイン(初回のみ)

```bash
python gphotos_cleanup.py login
```

ブラウザが開くので Google アカウントにログインし、Google フォトが表示されたら
ターミナルで Enter を押します。ログイン状態は `profile/` に保存され、以後は不要です。

### 2. 対象を確認する(何も変更しない)

```bash
python gphotos_cleanup.py scan
```

容量を消費しているメディアの概算件数と一覧(`downloads/scan.csv`)を出力します。

### 3. まずはお試し実行(削除なし・5 件だけ)

```bash
python gphotos_cleanup.py run --no-delete --limit 5
```

`downloads/` にファイルが正しく保存されることを確認してください。

### 4. 本実行(ダウンロード + ゴミ箱へ移動)

```bash
python gphotos_cleanup.py run
```

実行中はブラウザが自動で動きます。処理結果は `downloads/manifest.csv` に
1 件ずつ記録されます(ファイル名・サイズ・保存フォルダ・削除したかどうか)。

### 保存先のフォルダ構成(15GB ごとに自動分割)

ダウンロードしたファイルは、後で他のドライブへ移動しやすいように
**合計 15GB 以下のフォルダに自動で分割**して保存されます。

```
downloads/
├── batch_001/   ← 合計 15GB 以下
├── batch_002/   ← 合計 15GB 以下
├── batch_003/   ← いま書き込み中
├── manifest.csv ← 処理記録(どのファイルがどのフォルダにあるかも記録)
└── state.json   ← フォルダ番号の管理(消さないでください)
```

- 上限は `--batch-size-gb` で変更できます(1 ファイルだけで上限を超える巨大動画は、
  そのファイル単独のフォルダになります)。
- **いっぱいになったフォルダ(書き込み中でない batch_XXX)は、実行中でもいつでも
  別のドライブへ移動して構いません。** 移動済みフォルダの番号は再利用されません
  (`state.json` で管理)。

### ディスクの空きが少ない PC での運用

ダウンロード先の空き容量が 5GB(`--min-free-gb` で変更可)を下回ると、
ツールは自動で一時停止し、次のように表示します。

```
⚠ ディスクの空き容量が少なくなりました(残り 4.2 GB)。
  downloads の batch_XXX フォルダを別のドライブへ移動して空きを作ってください。
  空きを作ったら Enter、終了する場合は q + Enter:
```

batch フォルダを外付け HDD などへ移動して Enter を押せば、そのまま続きから再開します。
「少し進めては移動する」を繰り返すことで、**PC の空きが小さくても全量を退避できます。**

### オプション

| オプション | 説明 |
|---|---|
| `--out DIR` | 保存先ディレクトリ(既定: `downloads/`) |
| `--limit N` | 処理する最大件数(既定: 無制限) |
| `--no-delete` | ダウンロードのみ行い、削除しない |
| `--download-timeout 秒` | 1 件あたりのダウンロード待ち上限(既定: 900 秒。巨大な動画が多い場合は増やす) |
| `--batch-size-gb GB` | 1 フォルダあたりの合計サイズ上限(既定: 15) |
| `--min-free-gb GB` | 空き容量がこの値を下回ると一時停止(既定: 5) |
| `--pause 秒` | 1 件ごとの待機時間。一時的な 404 対策(既定: 2) |
| `--url URL` | 処理対象の一覧ページ(既定: サイズの大きい写真と動画)。下記参照 |

### 小さいファイル・他のカテゴリを対象にする(`--url`)

ツール自体にサイズの下限はなく、一覧ページに表示されるものはサイズに関係なく
処理されます。既定の「サイズの大きい写真と動画」ページはサイズの大きい順なので、
大きいものを消していけば小さいものが順に先頭に来ます。

もし小さいファイルがこのページに表示されなくなった場合は、他の「確認して削除」
カテゴリを対象にできます。[photos.google.com/storage](https://photos.google.com/storage)
を開き、「スクリーンショットと録画」「ぼやけた写真」などのカテゴリを開いて、
その URL をコピーして渡してください:

```powershell
python gphotos_cleanup.py scan --url "https://photos.google.com/quotamanagement/screenshots"
python gphotos_cleanup.py run  --url "https://photos.google.com/quotamanagement/screenshots"
```

これらのカテゴリページも「容量を消費しているもののみ」を表示する公式ページなので、
Pixel 特典分が対象外になる性質はそのまま保たれます。

なお、どのカテゴリにも表示されない容量消費ファイルを個別に特定する手段は
Google が提供していません(API でも不可)。各カテゴリを処理し終えたら、
[Google One のストレージ内訳](https://one.google.com/storage) で残量を確認し、
残りが小さければそこで完了とするのが現実的です。

## 重要な注意事項

- **削除されたメディアはゴミ箱に 60 日間残り、その間は容量を消費したままです。**
  すぐに容量を解放したい場合は [photos.google.com/trash](https://photos.google.com/trash)
  でゴミ箱を空にしてください(安全のため、このツールはゴミ箱を自動では空にしません)。
  60 日以内ならゴミ箱から復元もできます。
- Google フォトから削除すると、**同じアカウントで同期している全端末から見えなくなります。**
- ダウンロード先のディスクに十分な空き容量があることを確認してください
  (目安: Google One の使用量表示と同程度)。
- Google フォトの画面(UI)は予告なく変更されるため、自動操作が動かなくなることがあります。
  失敗時のスクリーンショットが `downloads/errors/` に保存されるので、問題の切り分けに使えます。
  連続で失敗した場合は安全のため自動で停止します。

## トラブルシューティング

### `scan` が 0 件になる / タイルを自動検出できない

ストレージ管理ページの DOM 構造は環境や時期によって異なり、タイルの自動検出に
失敗することがあります。その場合でも **`run` は使えます**:

1. `python gphotos_cleanup.py run` を実行する
2. タイルを自動検出できない場合、「最初の 1 枚を手動でクリックして開いてください」と
   表示されるので、ブラウザで最初の写真/動画をクリックして大きく表示する
3. 以降(ダウンロード → 削除 → 次へ)はすべて自動で進む

### ダウンロードが「ページが見つかりません (HTTP 404)」で止まる

連続してダウンロードしていると、Google の配信サーバーが一時的に 404 を返し、
ブラウザにエラーページが表示されることがあります(レート制限とみられます)。
ツールはこれを検知するとエラータブを閉じ、必要ならブラウザを自動で再起動して
続行します。失敗した項目は削除されずに一覧に残るので、後で再実行すれば
処理されます。頻発する場合は待機時間を増やしてください:

```powershell
python gphotos_cleanup.py run --pause 5
```

原因を調べたい場合は診断コマンドを実行してください:

```powershell
python gphotos_cleanup.py debug
```

ページの URL・各要素の件数・リンクのサンプルなどが表示され、
`downloads/debug/` にスクリーンショットとページ HTML が保存されます。
この診断出力(ターミナルの表示)があれば、検出ロジックを実際の DOM に
合わせて修正できます。共有時はファイル名などの個人情報にご注意ください。
- 途中で `Ctrl+C` で中断しても安全です。削除済みの記録は `manifest.csv` に残っており、
  再実行すれば残りから続行されます(削除まで行ったものは対象一覧から消えているため)。
  中断時に書き込み途中だったファイルは `downloads/_incoming/` に残りますが、
  次回起動時に自動で掃除されます(削除は保存確認後にしか行わないため、データは失われません)。
- **`--no-delete` モードでは再開時に重複ダウンロードされる**点に注意してください。
  削除しない限り対象一覧に残り続けるため、毎回先頭(最大サイズ)から処理されます。
  分割実行の運用は、削除まで行う通常モードで使ってください。

## 代替手段との比較

| 方法 | 容量消費分だけを選べるか | 削除 |
|---|---|---|
| **このツール** | ✅ quotamanagement ページが対象を絞ってくれる | ✅ 自動(ゴミ箱へ) |
| Google Takeout | ❌ 全メディアが混ざる(特典分も含む) | ❌ 手動 |
| Google Photos API | ❌ ライブラリ一覧・容量情報とも取得不可 | ❌ 削除 API なし |

## 免責

本ツールはブラウザ操作を自動化するものであり、Google の仕様変更等により
予期しない動作をする可能性があります。`--no-delete` での試運転と、
`manifest.csv` / ダウンロード済みファイルの確認を挟みながらの利用を推奨します。
